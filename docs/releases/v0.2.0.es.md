# MQTT Gateway v0.2.0 — SQLite, monitoreo y Telegram

Versión preliminar para evaluación. Sustituye la persistencia operativa en JSON por SQLite WAL, incorpora confirmación configurable de incidentes y añade notificaciones por Telegram con secretos administrados desde el panel.

## Incluye

- SQLite para backends editables, ajustes del panel, incidentes, outbox y secretos cifrados. Las rutas activas y métricas recientes permanecen en memoria.
- Monitoreo configurable en caliente: valores globales y ajustes opcionales por backend. Predeterminados: intervalo de 30 s, timeout de 2000 ms, 3 fallos para abrir incidente y 2 éxitos para confirmar recuperación. El timeout debe ser menor que el intervalo. Solo los sondeos automáticos confirman incidentes.
- Telegram para aperturas y recuperaciones confirmadas, interruptor maestro, chat global, desactivación o chat alternativo por backend, historial y pruebas de envío.
- Outbox transaccional persistente con reintentos limitados, tratamiento de HTTP 429 y retención. La entrega puede fallar o duplicarse; no se garantiza entrega exactamente una vez.
- Claves API y token de bot configurables desde el panel, de solo escritura, cifrados con AES-256-GCM. Las consultas devuelven indicadores de configuración, sin revelar los secretos.
- Validación JVM y nativa Linux en CI; publicación de imagen Docker para `linux/amd64` y distribución JVM completa con checksum SHA-256.
- Documentación y contratos para agentes alineados con el código. El código propio de esta versión se distribuye bajo GNU AGPL-3.0; se conservan los avisos de terceros.

## Antes de actualizar desde v0.1.0

1. Detén la instancia y respalda íntegramente su directorio o volumen de datos antes del primer arranque con esta versión. Para una base SQLite existente, respalda con el servicio detenido para conservar un conjunto coherente de archivos.
2. Prepara una sola vez un archivo privado `master.env` fuera del repositorio con `GATEWAY_MASTER_KEY`: exactamente 32 bytes aleatorios codificados en Base64 estándar. Restringe su acceso y guarda una copia segura. La [guía de preparación](../telegram-docker.es.md) incluye Bash y PowerShell.
3. Conserva el mismo directorio o volumen y, en Compose, el mismo nombre de proyecto. Inicia con esa clave maestra. La importación de archivos legados y las migraciones de esquema se ejecutan al inicializar el almacenamiento; no edites ni borres archivos legados para forzar otra importación.
4. Verifica `/q/health/ready`, el acceso administrativo, las rutas y los ajustes. SQLite será la autoridad para datos editables en los siguientes reinicios; cambiar el YAML de sembrado no reemplaza esos datos.
5. Configura las claves de los backends y el token de Telegram desde el panel. `apiKeyEnv` y `GATEWAY_TELEGRAM_BOT_TOKEN` no son el modelo de configuración vigente; las referencias legadas que puedan resolverse se importan una sola vez.

No generes una clave maestra nueva al reiniciar. Una clave incorrecta impide abrir los secretos existentes; perder la clave impide recuperarlos. No hay conversión inversa automática a v0.1.0: para volver, restaura el respaldo previo y usa la versión anterior con sus datos correspondientes.

## Probar la demo Docker Compose

Los comandos Bash siguientes suponen que ya preparaste `$HOME/.config/mqtt-gateway/master.env` siguiendo la guía. No uses una clave de ejemplo pública.

```sh
git clone --branch v0.2.0 https://github.com/kgvicente/mqtt-gateway.git
cd mqtt-gateway
docker compose --env-file "$HOME/.config/mqtt-gateway/master.env" up --build --wait
docker compose --env-file "$HOME/.config/mqtt-gateway/master.env" --profile test run --rm mqtt-tests
```

Panel local: `http://127.0.0.1:18085/gateway/`. Usuario `admin`, contraseña pública de demostración `local-demo-admin-2026`. No elimines el volumen para actualizar una instalación con datos.

## Descargas

- `mqtt-gateway-0.2.0-jvm.zip`: fast-jar completo, bibliotecas, licencias e instrucciones `RUN.md`. Requiere JRE/JDK 25 en Linux o WSL. No basta con ejecutar un JAR de aplicación separado de sus bibliotecas.
- `SHA256SUMS`: descarga junto al ZIP y verifica con `sha256sum -c SHA256SUMS`.
- Imagen versionada: `ghcr.io/kgvicente/mqtt-gateway:0.2.0`, para `linux/amd64`. Usa un volumen en `/app/data` y suministra la clave maestra externa. La imagen Docker utiliza JVM; la prueba de compilación nativa en CI no convierte esa imagen en un ejecutable nativo.

## Alcance de la evaluación

La demo valida MQTT 5 con la imagen fijada de Mosquitto 2.0.15 y el complemento archivado mosquitto-go-auth. Usa credenciales públicas y no configura TLS para MQTT; sirve para evaluación local. EMQX y VerneMQ mantienen cobertura de contrato HTTP, sin certificación de interoperabilidad MQTT real. No se publica imagen ARM ni ejecutable nativo independiente. No se verificó un envío a Telegram real; los contratos y escenarios de entrega se prueban con servicios simulados.

## English summary

This prerelease introduces embedded SQLite WAL persistence, configurable global/per-backend monitoring, confirmed incident and recovery notifications through Telegram, a transactional outbox, and write-only backend keys and bot tokens encrypted with AES-256-GCM.

Upgrade requires a persistent external `GATEWAY_MASTER_KEY` containing 32 random bytes encoded as Base64. Back up the stopped instance's full data directory before migrating, retain the existing data volume/project name, and preserve the master key. Editable data is authoritative in SQLite after initialization. Returning to v0.1.0 requires restoring the pre-upgrade backup.

The JVM ZIP requires Java 25 on Linux/WSL; the Docker image targets Linux AMD64 and runs on JVM. Native Linux is tested in CI, but no standalone native binary or ARM image is attached. Telegram delivery may fail or be duplicated; real Telegram sends have not been validated. Project-owned code in this release is licensed under AGPL-3.0.
